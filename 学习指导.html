一、LangChain4j 是什么

一句话：LangChain4j 是给 Java 生态 的 LangChain——一个把"大语言模型（LLM）"封装成正经 Java 库的框架。

它解决的痛点：

  • 厂商众多（OpenAI、Azure、Google Gemini、Claude、Ollama、通义……）各自 API 不同。LangChain4j 用统一接口抽象掉，换厂商只改一行配置。
  • LLM 输出是自由文本，不可靠。LangChain4j 提供结构化输出，直接转成枚举 / POJO / List。
  • LLM 无记忆、无外部工具、无私有知识。LangChain4j 提供记忆、工具调用（Function Calling）、RAG（检索增强）三板斧补齐。

一句话总结它的哲学：像写普通 Java 代码一样写 AI 功能，业务代码不感知背后是 LLM。

三、架构关系（核心概念分层）

业务代码 / Controller（REST 层）
▼ 调用
AI 服务（AiService）
你只定义接口 + 注解，框架生成实现
聊天模型 ChatModel
记忆 ChatMemory
工具 @Tool
▼
EmbeddingModel 向量化
EmbeddingStore 向量库
ContentRetriever 检索(RAG)
▼
DocumentLoader
DocumentSplitter 切块
RetrievalAugmentor

关键：AiService 是"心脏"。 它把上面所有零件（模型、记忆、工具、检索器）用接口 + 注解的方式"拼"起来，业务代码只跟接口打交道。

AiService 装配关系（代码视角）

AiServices.builder(Assistant.class)
    .chatModel(c)               // 装 模型
    .chatMemoryProvider(...)    // 装 记忆
    .tools(toolInstance)        // 装 工具
    .contentRetriever(r)        // 装 检索(RAG)
    .build();                   // 生成 Assistant 实例

四、LangChain4j 重要类及它们的关系

1. 模型层（最少要认识的接口）

类 / 接口作用关系
ChatModel同步聊天，chat() 返回完整回答最常用，任何厂商实现它
StreamingChatModel流式聊天，回调式逐段返回与 ChatModel 同族，二选一
EmbeddingModel把文本转成向量（embed()）供 RAG 用
ImageModel / AudioModel生成图 / 转写音频多模态专属
TokenCounter统计 token 数（计成本）配合监控

实现类关系：OpenAiChatModel、OllamaChatModel、GoogleAiGeminiChatModel 等全部实现 ChatModel 接口 —— 所以代码可无缝换厂商。

2. 消息与提示词层

类作用
SystemMessage / UserMessage / AiMessage三类消息，构成对话上下文
PromptTemplate{{变量}} 模板，自动替换参数
StructuredPrompt用 POJO 生成结构化提示词，参数自动映射字段

3. 数据解析 / 结构化输出层

类作用
ChatResponse一次模型回答的包装（含内容、token 用量）
output.structured.Description给 POJO 字段加"说明"，帮 LLM 理解字段含义
（隐式）返回类型转换AiService 依据方法返回类型自动把文本解析成枚举/数字/日期/POJO/List

4. 记忆层

类作用
ChatMemory对话记忆接口
MessageWindowChatMemory滑动窗口记忆（最多 N 条）
ChatMemoryProvider按 @MemoryId 为每个用户/会话提供独立记忆
持久化实现MapDB 等把记忆落盘，重启不丢

5. AI 服务层（核心中的核心）

类 / 注解作用关系
AiServices工厂：create()/builder() 生成接口实现装配器
@SystemMessage / @UserMessage声明系统提示词 / 用户消息模板用在接口方法上
@V把方法参数绑定到模板变量@UserMessage("...{{x}}") + @V("x")
@MemoryId标记"用户/会话标识"参数配合 chatMemoryProvider
@Tool标记方法为"模型可调用的工具"用在工具类方法上（可注入 AiService）
TokenStream流式 AI 服务返回的流对象StreamingChatModel 配套

6. RAG 层

类作用关系
Document / TextSegment文档与切块后的文本段检索的基本单元
DocumentSplitter把大文档切成小段每个段独立向量化
EmbeddingStore向量库（pgvector/Redis/内存等实现）存向量
EmbeddingStoreIngestor一键完成"切块→向量化→入库"组装上面两者
ContentRetriever检索器接口：根据问题取相关文本EmbeddingStoreContentRetriever 是常用实现
RetrievalAugmentor编排查询压缩/路由/重排等装配到 AiService
QueryRouter / Reranker / QueryTransformer高级 RAG：路由、重排、查询压缩挂在 RetrievalAugmentor 内
文档 → DocumentLoader → DocumentSplitter 切块
     → EmbeddingModel 向量化 → EmbeddingStore 入库
  （运行期）问题 → ContentRetriever 检索 → 相关 TextSegment
     → 拼接进提示词 → 交给 ChatModel → 基于资料回答

五、企业落地案例（14 个，含流程图）

案例 1：智能客服（个性路由 + 工具 + RAG + 持久记忆）

用户提问 └⟶ REST Controller └⟶ AiService.chat(@MemoryId 用户, 消息) ├⟶ ChatMemoryProvider 按用户隔离记忆 ├⟶ ContentRetriever 检索售后政策 (RAG) ├⟶ @Tool: 查订单 / 退款 / 改物流 └⟶ ChatModel 组织回答 → 返回 / 触发退款工单落库

案例 2：简历/JD 智能筛选（AI 信息抽取 + 结构化入库）

上传简历(PDF) └⟶ DocumentLoader 解析文本 └⟶ AiService 从文本中抽取简历实体 └⟶ 返回强类型 Resume POJO（姓名/技能/年限） └⟶ 序列化 JSON 入库 / 发消息队列 └⟶ 按技能向量化，支持语义检索候选

案例 3：工单自动分诊（结构化输出 + 分类）

用户提交工单文本 └⟶ AiService.analyze(工单) └⟶ 返回 {类别枚举, 紧急度, 归属团队, 建议动作} └⟶ 自动创建工单并派给对应团队 + 打标签

案例 4：企业知识库问答（多源 RAG + 重排）

用户提问 └⟶ QueryRouter 路由到正确知识源(订单/人力/财务…) └⟶ 多 ContentRetriever 并行检索 └⟶ Reranker 重排取最相关 └⟶ 拼接上下文 + 给 ChatModel → 回答 + 引用来源

案例 5：智能工单闭环 Agent（顺序工作流 + 工具 + 人工审核）

用户报障 └⟶ Agent1 受理：抽取问题&类别 └⟶ Agent2 诊断：检索知识库 + 查日志(工具) 给方案 └⟶ 非自动可解 → 主管 Agent (Supervisor) 派单给工程师 └⟶ Human-in-the-loop：关键操作等人工确认 └⟶ 解决后 Agent3 汇总并回执给用户

案例 6：舆情/评论情感监控（Embedding 分类 + 定时任务）

评论流 └⟶ EmbeddingModel 向量化 → 与情感样本库比对 └⟶ 或 AiService 判断情感枚举(正面/中性/负面) └⟶ 负面 → 触发告警 / 生成跟进工单

案例 7：多语言翻译与本地化（提示词模板 + AI 服务）

原文 + 目标语言 └⟶ AiService.translate(text, language) └⟶ @SystemMessage("你是专业{{language}}翻译") + 风格约束 └⟶ 返回目标语言文本 → 存入 CMS

案例 8：SQL / 报表智能生成（Text-to-SQL + RAG）

自然语言问题 └⟶ 检索目标表结构(约束) 拼接进提示词 └⟶ AiService 生成 SQL → 校验(沙箱/人工确认) └⟶ 执行查询 → 结果经 AiService 转成自然语言摘要

案例 9：会议纪要与行动项提取（文档处理 + 结构化输出）

录音转写文本 └⟶ DocumentLoader 读取 └⟶ AiService 产出 MeetingNotes POJO {主题, 决议, 行动项[责任人,截止], 风险} └⟶ 自动生成到项目管理系统 / 发通知

案例 10：合规审查（多 Agent 并行 + 汇总 + 人工复核）

待审文本 └⟶ 并行：Agent法律 / Agent品牌 / Agent隐私 ├⟶ 各自返回 {是否通过, 风险点} └⟶ 聚合 Agent 汇总风险清单 └⟶ 高风险 → 人工复核 (Human-in-the-loop) → 合规结论

案例 11：智能搜索增强（Query 压缩 + 混合检索）

用户多轮追问 └⟶ QueryCompression 压缩成独立问题 └⟶ 混合检索(向量库 + 全文检索) → 融合排序 └⟶ 返回相关片段 + 原文链接

案例 12：Agent 接入外部服务（MCP 工具）

用户意图"在新系统里给张三创建订单" └⟶ AiService(Agent) 决定用哪个工具 └⟶ 通过 MCP Server 调用 CRM 创建订单工具 └⟶ 返回操作结果 → Agent 组织话术回复用户

案例 13：模型路由与降级（多厂商 + 成本优化）

请求 └⟶ 路由策略(问题复杂度) ├⟶ 简单 → ChatModel(便宜小模型) └⟶ 复杂/失败 → 降级 ChatModel(大模型/备用厂商)

案例 14：流式聊天应用（SSE 流式 + 前端打字机）

前端消息 └⟶ Controller 返回 SSE 流 └⟶ StreamingChatModel 逐段推送 → 浏览器打字机展示 └⟶ 消息同时写入 ChatMemory 积累上下文

六、给你的学习路径

  1. 先用本总览建立整体地图——知道每个能力在哪、类之间什么关系。
  2. 再进各模块的学习指导.md，按文件优先级逐个跑。
  3. 带着"企业案例"去学：每学一个能力（如 RAG、工具、记忆），回来看它对应当标的案例，理解这个能力在真实产品里解决什么问题。
  4. 面试时能讲清 AiService + 四个组件（记忆/工具/检索/模型）如何组装，再结合 2~3 个亲手跑的案例（如客服、简历抽取、知识库），就是一份有说服力的 AI 开发能力证明。
建议路径：tutorials 入门 → customer-support-agent-example 看完整闭环 → agentic-tutorial 学编排 → rag-examples 学检索 → spring-boot-example 学生产落地。这条路走完，LangChain4j 的核心能力就都掌握了。
