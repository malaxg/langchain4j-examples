# pgvector-example 模块学习指导

## 模块概述

这是演示如何用 **PostgreSQL + pgvector 扩展** 作为 RAG 的向量库（EmbeddingStore）的示例。为什么它进了"必要学习"清单？因为 **PostgreSQL 是 Java 项目最普遍的关系库**，而 pgvector 让你不用额外引入专用向量数据库（如 Milvus/Pinecone），直接在现有 PG 上跑向量检索——成本低、运维少、Java 团队上手最快。

模块只有两个文件，都很短，重点是理解"向量入库 + 带元数据过滤的检索"这套配置。

## 总体在教什么

- 用 `PgVectorEmbeddingStore.builder()` 配置：host / port / database / user / password / table / dimension（向量维度）
- 用 Testcontainers 在测试里启动一个真正的 pgvector 容器
- 把文本向量化（EmbeddingModel）后 `add()` 进向量库
- 相似度检索 + **元数据（Metadata）过滤**：根据附加属性（如 userId、日期）缩小检索范围
- 理解 `dimension`（向量维度）必须与所选 Embedding 模型一致

## 学习路径（按优先级从高到低，逐一定义）

| 优先级 | Java 类 | 讲什么 | 是否必须学习 |
|--------|---------|--------|:---:|
| 1 | `PgVectorEmbeddingStoreExample.java` | 基础用法：配置 pgvector 存储 → 文本转向量 → 入库 → 相似度检索。先看懂这条主链路。 | 是 |
| 2 | `PgVectorEmbeddingStoreWithMetadataExample.java` | 进阶：给向量附加元数据 + 检索时按元数据过滤（`metadataKey(...).isEqualTo(...)`）。生产 RAG 高频需求。 | 是 |

## 学习建议

- **先懂 `dimension`**：向量维度必须和 Embedding 模型一致（如 OpenAI `text-embedding-3-small` 是 1536 维），配错会报错——这是新手最常踩的坑。
- **Metadata 过滤很重要**：真实系统里按租户/用户/时间过滤历史向量，这个文件教你如何按条件检索。
- 两个文件都用了 Testcontainers，实际运行需要 Docker；如果只想看代码，重点是 builder 配置和检索 API。
- 需要有自己的 PG（或 Docker 起 pgvector 镜像）。学会了本模块，你就能在现有 Spring + PG 项目里直接加 RAG，不必引入重组件。
