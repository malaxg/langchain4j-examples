# customer-support-agent-example 模块学习指导

## 模块概述

这是 LangChain4j 官方提供的**完整客服 Agent 应用**，也是"学了 tutorials 的知识点后，如何组装成一个能上线的真实系统"的最佳范本。它把前面散落学到的能力整合在同一个 Spring Boot 项目里：**AI 服务（AiService）+ 工具调用（BookingTools）+ 持久化对话记忆 + 检索器（RAG）+ REST 控制器**。

场景：一家叫 **Miles of Smiles** 的航空公司，用它提供的"客户支持条款"文档做 RAG，让 Agent 通过工具查询/取消/修改用户的机票预订，并全程具备对话记忆。

本模块的价值在于：**它是"知识点 → 真实产品"之间的那座桥**。看它之前建议先学完 `tutorials`，再看它回回路会非常清晰。

## 总体在教什么

- 如何用 Spring Boot 启动一个嵌入了 LLM Agent 的 Web 应用
- 如何用 `AiServices.builder()` 把模型、记忆、工具、检索器一次性装配进一个 AI 服务
- 如何用 `@Tool` 把"查航班/取消预订/修改预订"等业务方法变成模型可调用的工具
- 如何做 RAG：把条款文档切块入库，检索后作为上下文喂给 Agent
- 如何把 AI 服务暴露成 REST API，供前端调用
- 如何持久化会话（记忆）

## 学习路径（按优先级从高到低，逐一定义）

> 按"从外到内、从入口到依赖"的顺序读，会更容易理解。

| 优先级 | Java 类（完整类名见文件） | 讲什么 | 是否必须学习 |
|--------|---------|--------|:---:|
| 1 | `CustomerSupportAgentApplication.java` | Spring Boot 启动类。先看它：知道应用入口和默认端口。 | 是 |
| 2 | `CustomerSupportAgentController.java` | REST 控制器：把 AI Agent 的方法暴露成 HTTP 接口（`/customerSupportAgent`）。看它理解"用户怎么调到 Agent"。 | 是 |
| 3 | `CustomerSupportAgent.java` | **核心接口**：声明 `chat(@MemoryId String memoryId, @UserMessage String userMessage)`，这是 AI 服务契约本身。 | 是 |
| 4 | `CustomerSupportAgentConfiguration.java` | **装配中心**：在这里用 `AiServices.builder()` 把 ChatModel、ChatMemory、BookingTools、ContentRetriever 全绑到 Agent 上。读懂它 = 读懂整个 Agent 的组成。 | 是 |
| 5 | `BookingTools.java` | **工具类**：`@Tool` 注解的方法（获取航班、取消、修改预订、查看旅客）。模型靠调这些方法完成实操。 | 是 |
| 6 | `booking/BookingService.java` | 预订业务服务：内部提供航班/预订数据，是 BookingTools 真正干活的地方。 | 是 |
| 7 | `booking/Booking.java` | 预订领域对象（航班号、时间、价格等字段）。 | 否（了解字段即可） |
| 8 | `booking/Customer.java` | 旅客对象（姓名、护照等）。 | 否（了解字段即可） |
| 9 | `booking/BookingNotFoundException.java` | 业务异常类（预订不存在时抛出）。 | 否 |
| 10 | `src/test/.../CustomerSupportAgentIT.java`（含 `utils/JudgeModelAssertions.java`、`utils/ResultAssert.java`） | 集成测试：跑通并断言 Agent 行为（需真实模型/容器），用"裁判模型"评估回复质量。用于 CI，可了解不深读。 | 否 |

## 学习建议

- **优先理解装配**：`CustomerSupportAgentConfiguration.java` 是整个应用的大脑，把第 4 步读透，其余都迎刃而解。
- **看懂工具闭环**：用户问"我要取消预订" → Agent 决定调用 `BookingTools.cancelBooking()` → 返回结果 → Agent 组织回复。把这条链走通就掌握了工具调用产品化。
- **RAG 在配置里**：`ContentRetriever` 加载了 `miles-of-smiles-terms-of-use.txt` 条款，Agent 回答会先检索条款再作答，这就是 RAG 在真实应用里的样子。
- **跑起来看效果**：配置好 API Key，`mvn spring-boot:run` 后用 HTTP 发消息，观察 Agent 如何一步步调工具。
- 学会了这个模块，就具备了"把任意业务系统接入 AI Agent"的能力框架——面试时能拿它当代表作讲。
